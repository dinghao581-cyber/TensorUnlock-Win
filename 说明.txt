GPU 解锁（blhs2030/GPU-Unlock-windows 本机自建版）
=====================================================

这台机器上已经做好的事
  1. 固件五个 blob 全部由官方脚本从 NVIDIA 610.43.03 原始包生成，逐个 SHA 校验通过
     （目录 gpu-unlock\610.43.03\，含 NVIDIA-LICENSE）
  2. 用 VS2022 BuildTools + 解包的 SDK/WDK 10.0.22000.0 编出
     gpu_unlock.exe（277 KB）与 gpuunlock.sys（25 KB）
  3. gpuunlock.sys 已用自签名证书签名并 signtool verify 通过
  4. 模拟卡自检 verify 全程 PASS（SS0 写 0x88888888、SS1 写 0x8、FLR、GFW 校验 = 0）
  5. list 认到真卡：0000:02:00.0 10de:2203 RTX 3090 Ti（当前绑 nvlddmkm）
  6. Secure Boot 本机实测已是关闭状态，不用进 BIOS

使用顺序（只有第一次需要前两步）
  第 1 步 双击 开启测试签名.bat → 弹 UAC 同意 → 它会把 testsigning 打开
         （这一步是改启动配置，必须你点；屏幕右下角会长期出现“测试模式”水印）
  第 2 步 重启电脑
         注意：重启会断掉 8080 聊天后端，需要 F:\Strata-0.1.13\RESTART-optimized.bat 重新拉起
  第 3 步 以后每次开机后双击 GPU解锁.bat → UAC → 输入 YES → 屏幕黑一下再亮 = 完成
         卡已被驱动初始化时若被拒绝，改用 GPU解锁-pre-flr.bat
  随时看状态 GPU状态检查.bat（版本号 / PCI 枚举 / 只读寄存器探针，不写任何东西）

要知道的规矩
  断电就失效：解锁值存在显卡易失寄存器里，冷启动后必须重跑一次第 3 步。作者故意不做开机自启。
  收益范围：BF16/FP16 张量发射速率约 2 倍，对 ComfyUI 出图、prefill 有用；
            对量化 GGUF 的逐字解码没有提升（那条路是显存带宽瓶颈）。
  风险：这是测试签名内核驱动，可读写任意 PCI 设备的配置空间与 MMIO，会降低整机代码完整性防护。
        官方 3090 Ti 数字来自社区报告，仓库里没有原始日志，长期稳定性未验证。

回滚（管理员命令行）
  sc.exe stop GpuUnlock
  sc.exe delete GpuUnlock
  bcdedit /set testsigning off      然后重启
  删除本文件夹即可，无其它残留

2026-10-30 新增：GPU解锁面板.bat（一个窗口全干完，不用再散着点脚本）
  主脚本文件名叫 gpu-panel.ps1（英文名是故意的）：cmd 读 .bat 用的是 OEM 代码页 936，
  .bat 正文里只要有一个非 ASCII 字节就会被解成乱码命令，窗口一闪就没了；
  所以 GPU解锁面板.bat 正文全是 ASCII，它只调用 ASCII 路径的 gpu-panel.ps1。
  老名字的 GPU解锁面板.ps1 留着一个转调用的空壳，旧快捷方式照样能用。
  界面是一条**从上往下点的 7 步流水线**，每步一张卡片，卡上写清：
      第几步 · 这步干什么 · 状态徽标（未开始 / 进行中 / 成功 / 失败 / 要动手 / 等前一步）· 一句话结论
  点卡片任意位置 = 看这一步的**原始报告**（命令原文 + 输出 + 退出码），显示在右栏「这一步报了啥」。
  没跑到的步骤按钮是灰的（写着「等第N步」），所以不会点乱。
  顶部大字 = 总线：绿＝已解锁、红＝未解锁、灰＝还没判定，旁边写依据数字；下面一行写「进度 N/7 · 现在该点第X步」。
  右栏上半 = 本机体检清单（管理员 / Secure Boot / 测试签名 / 证书 / 驱动服务 / 固件 / 显卡 / 显存占用）。
  底部按钮：自动跑只读三步（1+2+4，不写任何东西）/ 复制全部报告 / 存报告到文件（dist\报告-<时间>.txt）
            / 打开说明 / 立即重启（10 秒内可用 shutdown /a 撤销）
  七步分别是：
      1 体检环境前提（只读）        2 模拟自检 verify（不碰真显卡）
      3 开启测试签名 + 装证书（要重启） 4 只读探针 real --probe（顺手把第5步的路径选好）
      5 一键解锁（真显卡，会黑一下；路径下拉：常规 / pre-flr / 冷启动）
      6 BF16 实测算力 = 成败判定     7 收尾：规矩与回滚（只显示，不执行）
  打开时自动跑一次第 1 步体检，所以一开屏就知道"到底缺什么、激活了没有"。
  判定口径（本机实测基线，2026-10-30 12:29 未解锁状态）：
      BF16 4096x4096 matmul = 56.33 TFLOPS；FP16 = 57.00 TFLOPS
      ≥100 TFLOPS 判为已解锁；≤75 判为未解锁；中间显示"模糊区"提示重测
      寄存器口径：SS0=0x88888888 且 SS1=0x8 ＝ 已解锁
      顶部结论的优先级：第6步实测数字 > 第5步读回 PASS > 第4步探针寄存器值
  自检命令（不弹窗、不动硬件；全绿输出「SELFTEST 结论 FAIL=0」）：
      powershell -NoProfile -ExecutionPolicy Bypass -STA -File gpu-panel.ps1 -SelfTest
  出图验收（灌示例数据后真截图，用来检查排版没破版）：
      powershell -NoProfile -ExecutionPolicy Bypass -STA -File gpu-panel.ps1 -Shot C:\temp\panel.png
  双击 GPU解锁面板.bat 闪退过（2026-10-30 已修）：原因是那版 .bat 正文带中文，cmd 按 936 码页解坏，
      报 "'~dp0"' is not recognized / 'll' is not recognized 然后窗口秒关。现在正文纯 ASCII，已复测能开。
      以后再改 .bat：正文一律英文；.ps1 正文可以中文但必须存成「UTF-8 带 BOM」。
  桌面右下角「测试模式 / Windows 10 专业版 / Build …」三行水印（可选项，2026-10-30 加）：
      这三行是系统在「测试签名」模式下画在桌面层的。唯一官方开关 bcdedit /set testsigning off
      会让没签名的解锁驱动加载不了＝解锁失效，所以不能关，只能盖住。
      开启：双击 wm-hide.bat   （右下角贴一块黑色贴片，鼠标穿透，不遮任务栏时钟）
      关闭：双击 wm-show.bat   （立刻恢复原样，不留痕迹）
      贴片大小/层级可调：powershell -NoProfile -ExecutionPolicy Bypass -STA -File wm-hide.ps1 -SelfTest
                        参数 -CoverW 680 -CoverH 190 [-TopMost] [-Color Black]
      开机自动贴：等你确认好用再注册计划任务；现在没有安装任何计划任务，随时可回滚。

================ 开机自动解锁（2026-10-31 定案，推荐用这条） ================
结论：第5步（运行中解锁）永远不可能成功——那时 nvlddmkm 已接管显卡、GSP 固件已跑起来，
      写寄存器被拒（unlock_transaction_gfw error=-138 firmware_started=0）。
      唯一可行路径：开机、驱动绑定之前解锁（--cold），已验证成功。

实测（2026-10-31 00:0x，驱动仍是 617.42）：
      SS0=0x88888888  SS1=0x00000008  unlock read-back: PASS
      BF16 116.79 TFLOPS / FP16 117.08 TFLOPS（未解锁基线 56.33 → 2.07 倍）

三个计划任务（SYSTEM、最高权限）：
      GpuUnlockOff        系统日志 Event 1074（关机/重启发起）→ 禁用显示适配器，让下次开机是冷态
      GpuUnlockBoot       开机 → 先判断是否冷态（不是冷态就只写日志、绝不动硬件）→ gpu_unlock.exe real --cold --yes
                          → 无论成败把适配器启用回来 → 再跑 --probe 记录 SS0/SS1
      GpuUnlockBootRescue 开机 +5 分钟 → 显卡还不是 OK 就强行启用 / 重启设备
      日志：C:\ProgramData\GpuUnlock\boot-unlock-<时间戳>.log / disable-at-shutdown.log

桌面图标修复（v3.2 新增，解决「重启后桌面图标变小 / 右键菜单失灵」）：
      原因：装了 360 桌面助手这类接管桌面层的软件，重启后会把 Windows 的图标视图状态打回默认（48px），
            严重时 SysListView32 根本建不出来（桌面图标层丢失 → 右键没反应）。跟显卡解锁无关，
            但装解锁包的人常同时装这类软件，所以把修复一起打包进来。
      组成：
            desk-fix.ps1             单独可跑：恢复图标大小 + 图标层丢了就重建（必要时重启一次 explorer）
                                     参数 -IconSize 64 指定并记住；-CheckOnly 只看不动；
                                          -Stop360 顺手停掉 360 桌面助手（需管理员）
            面板第二排三个按钮       桌面修复 / 图标 小 − / 图标 大 +（当前大小显示在右边）
            计划任务 GpuUnlockDeskFix 每次登录 20 秒后自动跑一遍，图标被改小会自动改回来
      日志：C:\ProgramData\GpuUnlock\desk-fix.log      配置：C:\ProgramData\GpuUnlock\desk.cfg
      实测：图标 48 → 64 后重启 explorer，listview 间隔 cy 147 → 172（图标确实变大）；
            任务手动触发 lastResult=0，日志 ok=True；面板 SelfTest 全项 PASS。
